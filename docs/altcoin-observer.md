# 山寨币建仓观察

这是只读的前瞻研究模块，不是自动交易策略，也不保证能够识别底部或预测拉盘。默认观察 AWE、ARPA、AGLD、BEL；每个用户最多配置 20 个 Ethereum / Base 代币。Binance 交易对必须与项目代号一致，目前不支持倍数合约或未上市币种的候选判断。

## 页面与权限

- 状态：观察列表、机会分、风险分、24 项选币指标及评分条件、来源时效、已收盘日线、持仓、转账、权限事件和新闻。
- 交易记录：候选/风险信号、当时的完整证据、参数及 1h / 24h / 7d 前瞻净价格变化。这里没有真实订单。
- 配置：更新周期、门槛、四组因子的独立开关与风险阈值、币种、合约、Governor 地址、钱包标签和通知开关。
- `radar:view`：查看自己的观察与信号。四个默认角色均拥有。
- `radar:manage_self`：管理自己的观察；analyst / trader / admin 默认拥有。后台只为同时具备查看与管理权限的活跃用户采集。

管理员也不能通过观察接口读取其他用户的配置、地址标签和信号。权限撤销、用户停用或观察项更新后，正在执行的旧采集结果不会落库。Viewer 只有只读权限，不会自动启动付费或高频采集。

## 自动发现低市值币种

状态页新增独立扫描池，不再只扫描手工填写的四个项目，也不受深度观察的 20 项上限限制。默认筛选条件为：

- Binance USDT 永续与 Upbit 韩国现货的代码交集。
- 流通市值 100 万至 3 亿美元，包含边界；不是 FDV，也不是单枚币价。
- Upbit KRW / BTC / USDT 全部报价市场。用户可只选 KRW、BTC 或 USDT。
- 默认排除 Upbit `warning=true` 和警告状态未知的项目；普通 caution 标记单独显示，不自动解释为操纵。
- 最低报告成交额默认为 0，即没有成交额过滤，可由用户提高。筛选命中本身没有通过盘口流动性检查。
- 每 15 分钟自动扫描，可调整至 24 小时；并支持单独 Binance、单独 Upbit、两边并集。每位用户的筛选条件独立。

Binance 列表只取 `/fapi/v1/exchangeInfo` 中 `TRADING`、`PERPETUAL`、USDT 报价及保证金币种、`underlyingType=COIN` 的合约。不含交割合约、币本位、USDC 合约及非加密资产合约。Upbit 使用韩国站 `api.upbit.com/v1/market/all?is_details=true`，不与新加坡或其他地区的交易对混用。

币种身份优先使用 CoinGecko 的 Upbit 实际交易对 `coin_id` 映射，其次使用代码加完整英文名称或目录内唯一代码。多个候选 ID 冲突时不猜测，不自动去掉 `1000` 等倍数合约前缀。结果分别标注映射方法；**跨平台代码相同不等于跨平台合约身份已核验**。唯一代码匹配只能作为筛选线索，不能授权交易。第三方目录及重命名可能滞后，未匹配币种和覆盖缺口均展示，不声称已覆盖全部上市资产。

市值按明确的 CoinGecko ID 分批查询 `/coins/markets`，再校验返回代码与记录对应；单次最多 200 个 ID。正市值和有效供应商 `last_updated` 均必需，市值缺失、为零、负值、身份不符、过期或未来时间异常的记录不入选。FDV、报告 24h 成交额、24h 涨跌幅仅为背景数据；成交额不是 Upbit 或 Binance 的单平台成交额。排除已知稳定币名单，但不保证覆盖所有新稳定币。

上市列表和市值超过一小时即不可用于筛选。目录缓存 24 小时、Upbit 交易对映射缓存 6 小时、上市列表和市值请求缓存 15 分钟，保留原始时间；每日上市名单变化或映射缓存更新可能有延迟。映射按稳定的 base/target 排序读取，最多十页，未到末页会标记部分覆盖。若将扫描周期设为一小时以上，结果会在下次采集前进入过期状态。手动刷新只加入队列，不绕过缓存、60 秒冷却或供应商限速。

未设置 CoinGecko Demo Key 时，同一进程内该主机的请求至少间隔 12.1 秒；有 Key 时至少间隔 2.1 秒。后台深度观察与扫描共用限速和缓存。额度仍由供应商决定，HTTP 429 按 Retry-After 冷却；不轮换出口或规避限制。首次完整扫描可能需要数分钟，网页读取已保存结果，不等待远端全量扫描。

公共上市及市值快照跨用户共享，后台按具备权限且开启扫描的用户中的最短周期运行；个人过滤、观察列表和信号不共享。个人暂停只停止其触发自动扫描，不禁止读取其他活跃用户触发的公共更新。没有任何有权用户启用时不采集。任务有 300 秒租约和 240 秒超时，结果持久化到 SQLite；当前只保留最新公共扫描快照，不把它当作历史成分股数据库。部分供应商失败时保留可核实部分并标注缺口；整轮超时后旧结果不能继续充当有效命中。

“配置观察”会再次核对 CoinGecko 身份、Ethereum / Base 合约地址和 Binance USDT 现货上市状态，然后仅预填原来的观察表单，需用户保存。原生币、其他链和没有 Binance 现货的项目可以出现在扫描池，但目前不能直接进入链上深度观察。**扫描池不自动对全部币种运行 24 项深度因子，不自动下单，也不把市值筛选命中叫作建仓信号。**

接口沿用 `radar:view` / `radar:manage_self`：`GET /api/radar/discovery`、`PUT /api/radar/discovery/settings`、`POST /api/radar/discovery/refresh`、`POST /api/radar/discovery/prepare/{coin_id}`。Viewer 不可修改条件或触发采集。

来源：[Binance Exchange Information](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Exchange-Information)、[Upbit 交易对列表](https://docs.upbit.com/kr/reference/list-trading-pairs)、[CoinGecko Exchange Tickers](https://docs.coingecko.com/reference/exchanges-id-tickers)、[CoinGecko 市值接口](https://docs.coingecko.com/reference/coins-markets)。

## 自动更新

启动正常的 Web 服务即可，无需让浏览器保持打开：

```bash
python3 -m pip install -e .
crypto-lab-web --host 127.0.0.1 --port 8093
```

默认每个币种采集完成后 300 秒再次排队，用户可设 60 至 86400 秒。任务串行执行并按主机限速，因此这不是每个币种严格同时刷新的行情流，也不是 WebSocket 逐笔实时信号。浏览器每 15 秒读取已经保存的观察结果，不直接调用数据供应商。手动刷新受 60 秒冷却保护。

任务租约、下次更新时间和采集结果存入 SQLite，进程重启后继续排队；租约 240 秒，单次采集上限 180 秒。一个数据库只建议运行一个 Web worker。采集器缓存公共响应，缓存命中保留原始采集时间，遇到 HTTP 429 遵守 Retry-After，遇到 HTTP 403 暂停该主机请求一小时，不绕过访问限制。

运行机器必须保持开机、联网且不休眠。长期部署请用 systemd、容器重启策略或操作系统进程管理器；不能把终端进程或临时公网隧道当成全天候服务。已有部署需保留原来的 `CRYPTO_LAB_SECRET_KEY`，否则旧交易所密钥无法解密。不要把默认管理员密码或开发密钥用于公网。

环境变量：

| 名称 | 作用 |
| --- | --- |
| `CRYPTO_LAB_RADAR_ENABLED` | 默认 `1`，设为 `0` 关闭本进程的后台观察任务 |
| `CRYPTO_LAB_COINGECKO_DEMO_KEY` | 可选的 CoinGecko Demo Key，仅发送给固定 CoinGecko API 主机，不返回浏览器 |
| `CRYPTO_LAB_DB` | 沿用应用数据库设置 |

## 数据定义

| 类别 | 实际来源与口径 | 有效期 |
| --- | --- | --- |
| 市值 | CoinGecko `/coins/{id}`，校验 ID、代号、链上地址。流通市值为供应商 market_cap；总供给估值为 total_supply × USD price；FDV 为供应商 fully_diluted_valuation，不把三者混用 | 15 分钟 |
| 现货 | Binance Spot 24h ticker、前 100 档盘口和最近 30 根已收盘日线。1% 深度取买卖两侧较小名义额，属于有限档位下界 | 5 分钟 |
| 日线与基准 | Binance Spot 币种、BTCUSDT、ETHUSDT 各最多 120 根 UTC 日线。排除未收盘、重复、缺日及超过一日加 120 秒仍未更新的序列；日线截至时刻单独展示，最少需 31 根 | HTTP 观测有效 1 小时；指标每日变化 |
| 合约 | Binance USD-M 当前 OI、本期资金费、连续 25 个小时的 OI 样本。24h 变化按合约数量比较，不将价格上涨导致的名义额增长当成增仓 | 2 小时 |
| 持仓 | Blockscout 前 50 个持币地址。仅比较两次都出现、余额有效的共同地址，至少 10 个；两次观测间隔须为 1 至 48 小时，优先取约 24 小时前的基线 | 30 分钟 |
| 转账 | Blockscout 最近一页，按交易哈希和日志序号去重。大额交易所转入风险仅检查近 24 小时，且接收方必须是用户明确标注的交易所地址 | 30 分钟 |
| 权限 | 固定公共 RPC 的 finalized 区块：owner、paused、标准 Safe owners/threshold、配置 Governor 的 guardian/timelock、可识别的 token admin/upgrader 权限；Blockscout 最近 90 天已执行日志 | 2 小时 |
| 新闻 | CoinDesk、Cointelegraph、Decrypt 公共 RSS，近 7 天标题按项目全名或 `$SYMBOL` 匹配。安全/退市/解锁等词只触发待复核，不作为事实认证 | 30 分钟 |

有效期按供应商观测时间计算；持仓、转账和 RSS 没有可靠的供应商快照时间时，使用最初 HTTP 响应接收时间。这**不能测量索引器自身滞后**。持仓不固定在同一区块，地址可能是交易所、桥、金库或同一实体，持仓增长不等于买入。USDT 与 USD 未做脱锚换算。

权限读取只覆盖列出的接口，不是完整审计；未知权限架构不能通过候选门槛。没有 owner 也不等于完全不可升级。标准 Safe 阈值不证明签名人相互独立，模块、代理、mint/freeze 等其他路径需要另行审计。权限历史返回超过分页上限或无法完整读取时，标记为不完整。只展示成功读取的当前多签配置，不声称近期没有变更。

## 基础规则

机会分是人工规则的诊断分，不是训练模型、概率或经过收益验证的 alpha。以下为 v1 原始基础分，满分 100；v2 按启用的因子组缩放这些分数，默认缩放为 80 分：

| 条件 | 分数 |
| --- | --- |
| 流通市值落在用户区间 | 10 |
| 报告 24h 成交额达到门槛 | 5 |
| 流通 / 总供给在 0.6 至 1.01 | 5 |
| 相对近 30 根已收盘日线最高价回撤 20% 至 65% | 20 |
| 日线 RSI14（简单平均涨跌额，不是 Wilder 平滑）在 25 至 45 | 15 |
| 近 7 日下跌，24h 上涨 0% 至 8% | 15 |
| 买卖价差、双边深度同时达标 | 10 |
| 本期资金费绝对值不超过 5 bps | 5 |
| 可比大户地址合计余额增加至少 1% | 15 |

风险分独立计算，最高 100。低流通、极深回撤、极端超卖、短期暴涨、薄盘口、来源价差、极端资金费、OI 激增、地址集中度、持仓流出、已标记交易所大额转入、单签管理员、近期已执行权限变更和新闻风险词会加分。高风险不意味着已经证实操纵。

默认机会分至少 60、风险分不超过 35、来源有效覆盖至少 85%。市值、现货、持仓、转账和权限均为必需来源，任何一个缺失、过期或部分失败都会阻止候选；币种身份、可比持仓基线、流动性和市值门槛也必须满足。代币暂停、近期权限变更、新闻风险词或严重价格偏差需要复核。首次启动一般只能显示“积累样本”或“数据不全”。

新闻和衍生品不是绝对必需项，但缺失会降低覆盖率和可得分数。启用新增因子时，来源覆盖率是八个类别中有效类别的比例；全部关闭时仍按原七类计算。不是所有链、交易所或新闻的覆盖率。单次盘口、总成交量和转账不能确认刷量、对敲、操纵主体或未来拉盘。

## 规则 v2：选币因子

`altcoin-observer-v2` 新增 24 项诊断指标，分为四组。每组最多 5 分，默认全部启用。机会分计算为：

```text
机会分 = 原始基础分 * (100 - 启用组数 * 5) / 100 + 新增因子得分
```

缺失值不得当成 0、利好或重新分配权重。默认启用评分项的有效权重至少覆盖 80% 才能成为候选，该门槛与来源覆盖率分开检查。不加分的背景指标不计入评分覆盖率。全部关闭新增组时回到基础规则权重，但身份、权限、流动性等原有硬门槛不变。开启因子组也同时开启该组的额外风险规则。

| 组别 | 指标 | 加分条件，总计 5 分 |
| --- | --- | --- |
| 相对强弱与趋势 | 7/30/90 日动量、相对 BTC 7/30 日和相对 ETH 7 日、距 SMA20、SMA20 五日变化、SMA20/SMA60、价格 Z-score20 | 相对 BTC 七日为正 +2；相对 BTC 三十日为正 +1；相对 ETH 七日为正 +1；SMA20 五日变化为正 +1 |
| 量能与流动性 | 7 日相对前 30 日量能、7 日主动买入占比、Amihud30、报告成交额/流通市值 | 量能比在 1.2 至 3 倍 +2；主动买入占比在 52% 至 65% +2；Amihud 不超过个人阈值 +1 |
| 波动与尾部风险 | 年化波动率30、ATR14/价格、90 日最大回撤、BTC Beta30、BTC 相关性30 | 波动率不超过阈值 +2；ATR 比例不超过阈值 +2；90 日最大回撤不差于 -60% +1 |
| 市场环境与杠杆 | BTC 距 SMA60、BTC 七日收益、永续标记价相对指数价偏离、合约 OI/现货成交额、FDV/流通市值 | BTC 位于 SMA60 或上方 +2；BTC 七日收益大于 -10% +1；永续偏离绝对值不超过阈值 +1；OI/现货成交额不超过阈值 +1 |

### 计算口径

- 收益使用已收盘价格。相对强弱为币种总收益倍数除以基准总收益倍数减一，不是两个百分比直接相减。BTC/ETH 与币种日期必须对齐。
- 量能比为最近七日平均 USDT 成交额除以此前不重叠的三十日平均成交额，需要至少 37 根日线。主动买入占比为七日 taker-buy quote volume 之和除以七日 quote volume 之和，不是资金净流入。
- Amihud 为 30 日 `mean(abs(simple_return) / quote_volume) * 10^10`，单位 bps/百万 USDT，是非流动性代理，不是下单滑点估计。零成交额日不能算作低冲击。
- 波动率为 30 个日对数收益的样本标准差乘 `sqrt(365) * 100`。ATR 为最近 14 日真实波幅的简单均值，不是 Wilder 平滑。Z-score 使用 20 日收盘价样本标准差。
- 最大回撤以 91 个收盘价形成的 90 日路径计算，不包含日内极值；不足 91 根时缺失。Beta 与相关性基于同日 30 个对数收益，BTC 方差接近零时不计算，短样本结果不稳定。
- 永续偏离为 `markPrice / indexPrice - 1`，转换成 bps，不是年化基差收益。OI/现货成交额均取 Binance 同币种 USDT 名义额，是存量/流量比，不是全市场杠杆。合约与现货按各自的最新观测，非原子同步；界面列出两者时间。
- FDV/市值与报告换手代理只作背景展示，不重复加分；解锁压力不能只看 FDV。所有成交量指标都可能受刷量影响。

### 默认风险阈值

每用户可调整年化波动率上限 150%、ATR 上限 10%、Amihud 上限 100 bps/百万 USDT、永续偏离上限 100 bps、OI/现货成交额上限 5 倍。参数只是可解释的初始假设，不是回测最优值。

波动或 ATR 任一超限加 15 风险分；Beta 大于 2.5 加 5；量能大于五倍且七日收益不为正加 10；Amihud 超限加 10；近三十日有零成交额日加 10；永续偏离或 OI 比任一超限加 15；BTC 七日下跌超过 10% 加 10。风险总分仍封顶 100。这些异常只提示复核，不能证明操纵。

### 尚未接入自动评分

解锁日历、TVL/协议收入、活跃用户、社交情绪、开发者活动与板块轮动仍列为待接入。需要可靠授权、项目映射、机器人过滤及历史时点记录；不会用新闻条数冒充全网关注度，也不把今天的 TVL 或后来公告填入历史回测。

研究依据：[Common Risk Factors in Cryptocurrency](https://www.nber.org/papers/w25882) 研究市场、规模与动量等共同风险因子；它不验证本工具的阈值，也不保证当前山寨币收益。字段口径参考 [Binance Spot REST API](https://github.com/binance/binance-spot-api-docs/blob/master/rest-api.md#klinecandlestick-data) 和 [USD-M Mark Price](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Mark-Price)。

## 信号与验证

候选和风险状态变化会保存冻结证据，同类信号最多每日重复一次，并写入应用通知中心。已有外部 Telegram / 邮件 / Webhook 渠道只进入现有通知队列；本模块不自动派发外部消息，也不会绕过原有通知派发开关。

冻结证据包含规则版本、完整个人参数、因子数值、条件与分数。v1 历史不会被改写成 v2 绩效；观察历史列出版本，比较效果必须按版本和参数分组。实时概览按当前规则重评，新日线缺失时不沿用旧因子分。

候选的前瞻记录使用信号时的卖一价作为假定入场、到期后首次有效买一价作为假定退出，扣除参数中保存的双边手续费与滑点：

```text
net = exit_bid * (1 - slippage) * (1 - fee)
      / (entry_ask * (1 + slippage) * (1 + fee)) - 1
```

报价必须来自身份核验通过的同一交易对，到期容忍窗口为更新间隔的两倍，最少 120 秒、最多 900 秒。未拿到有效报价则标记缺失，不用后来行情补造当时结果。记录实际观测时间，不伪装成精确时刻成交。暂停或服务中断期间无法承诺收益样本完整。

这不是订单回测：没有真实成交量匹配、冲击、资金费、保证金或平仓机制。观察快照最多保留 30 天且每币种最多 3000 条，冻结信号及前瞻结果保留 180 天（清理在后续采集完成时执行）。SQLite 文件需要运维定期备份并检查磁盘空间；清理行不等于立即缩小数据库文件。删除观察项会连同其历史一起删除。尚未有样本外绩效结论；积累真实历史后才适合评估命中率、误报率、交易成本敏感性及横截面基准。
